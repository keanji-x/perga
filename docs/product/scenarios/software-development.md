# 场景一：软件开发 User Flow 与体验设计

软件开发是 Perga 现阶段**首个重点打磨的场景**。本文刻意不谈底层实现，只从**开发者真实工作流（User Flow）**出发，描述一个人在并行推进多条开发任务时，从发起需求到合并归档的完整体验设计——包括顺风主流程，也包括真实开发里最耗心力的三种逆风流程。

## 体验目标

> **让开发者从“在十个终端里当 AI 保姆”，变成只做三个高杠杆动作的负责人：定边界 → 偶尔纠偏与裁决 → 看证据拍板合并。**

Perga 在开发场景里不与单厂工具拼“补全一行代码有多快”，而是解决另一个更痛的问题：**当你同时推进 3–8 个跨小时乃至跨数天的开发任务时，既不用反复切窗口盯梢，也不用闭眼盲信合代码。**

---

## 前置体验原则：按任务轻重自然分档，绝不一刀切

真实研发里既有 10 分钟的小修，也有跨 3 天的大改。如果改两行样式也要走“先写方案 → 人工对齐 → 双路独立审查”，工具会立刻变得沉重僵化：

- **轻改动（文案/样式微调、局部修 Bug、补单测）**：一句话发出后直奔实现与受影响验证，几分钟内给出精简 Diff 与绿灯即可收口，不强加前置对齐仪式。
- **重改动（新特性、跨模块重构、改动数据结构/公开契约/权限边界）**：自动进入完整的“先对齐边界 → 隔离实现 → 独立异构审查 → 全量验证 → 导览式审阅合并”闭环。

---

## 一、主流程：一条重度开发任务的完整 User Flow

### Step 1 · 发起任务：零表单起手，纪律隐形继承（0–60 秒）

1. 用户在项目对应的分组下点击新建任务，只做一件事：**输入一句话需求，或直接粘贴一个 GitHub Issue 链接**，按回车发送。
2. **没有前置弹窗**要求用户选模板、填测试命令、选分支策略或配置审查模型——项目级默认验证方式、偏好的审查模型与仓库规范自动继承生效。
3. 系统在后台静默准备好独立隔离现场；任务负责人先只读了解项目规范与关联代码，而不是上来就闷头改文件。
4. 几十秒内，主屏立出一份 **30 秒能读完的《目标与边界》**（改什么、不改什么、准备怎么验证）。如果需求清晰，直接给出推进方案；仅在存在真实歧义时，在边栏抛出 1–2 个简短选择题。

### Step 2 · 对齐边界：3 分钟定锚，然后放心离手（1–3 分钟）

1. 用户扫一眼主屏的《目标与边界》以及即将执行的阶段预览（实现 → 独立审查 → 全量验证 → 提 PR 与盯 CI）。
2. 用户不必自己去改文档，只需在边栏补充或确认一句（例如“不要改动公开 API，审查换另一个模型看，开始吧”）。
3. 确认后，主屏切入清晰、只读的实时进度视图并自动推进。
4. **关键体感**：用户此时可以**立刻切去侧边栏里的下一条任务**，或者离开电脑——边界、审查分工和验证门槛已经锁死，不需要守在屏幕前怕它跑偏。

### Step 3 · 并行巡航与随时插手：默认安静，一跳直达现场（运行中）

1. **多轨并行靠侧边栏 `Focus` 统管**：开发者不需要专门逛重型全局大盘，扫一眼侧边栏即可掌握所有进行中的任务。视觉信号严格压成极克制的三档，绝不制造小红点焦虑：
   - **等你拍板 / 出现卡点**（最高优显眼）：需要人类确认、审查卡住、CI 失败、或已全绿待合并；
   - **后台静默运转中**（极弱呼吸态）：正在写代码、正在独立审查、或正在静默等远端 CI，绝不弹窗打扰；
   - **普通更新**（轻提示）：常规阶段进展，不催促。
2. **随时巡看，无需翻聊天记录**：用户点进任意一条运行中的任务，主屏一眼即可看出当前卡在或跑在哪个阶段，以及紧贴节点下方的极简状态脚注（验证通过/运行中/失败、关联的代码或设计文档链接）。
3. **打破黑盒，一跳纠偏**：点击进度节点上的执行者标识，直接进入该 Worker 的实时工作流。发现思路走偏时，用户直接发一句纠偏指令（Steer）把它拉回正轨，或者当场打断、换更强模型接着跑。

### Step 4 · 导览式验真与拍板合并：花 1 分钟只看最值钱的代码（收口一刻）

当独立审查阻塞项清零、全量验证通过、PR 创建且远端 CI 全绿后，侧边栏 `Focus` 轻提醒该任务进入 **Ready to Merge**。

传统工具到这里往往甩出一大坨按字母序排列的几千行原始 Diff，逼人在“硬看半小时”和“闭眼盲合”之间二选一。Perga 在收口一刻将主屏自然收束为一份**可十秒扫清全局、也可随时下钻关键代码的交付简报**：

1. **一句话交付结论 + 导览式代码审阅（Guided Diff）**：
   - 自动把改动按风险与核心逻辑分层——**核心实现与高风险边界改动**（数据变更、公开契约、状态流转、权限逻辑）置顶，**机械改动与测试补丁**折叠在后；
   - 点击任意条目直接侧滑展开干净 Diff，让人花 1 分钟就能把最关键的 50 行代码看踏实。
2. **异构独立审查往返摘要**：
   - 清晰列出另一家独立审查模型挑出了哪几个问题、分别在后续如何修掉、以及复审确认零阻塞；
   - 点击任意一条审查意见，直接定位到对应的“问题代码 → 修复 Diff”。
3. **不可伪造的客观绿灯**：
   - 由系统直接记录并展示真实跑过的测试命令、结果状态与 PR CI 全绿链接，不依赖模型口头汇报“我测过了”。
4. **风险与边界提醒**：
   - 显式提示是否涉及迁移、配置变化或已知未覆盖项。

无论在桌面端还是手机端，用户扫完硬证据并抽检核心代码后，从容确认合并。

### Step 5 · 合并归档：干完即净，决策永久留痕

1. PR 合并完成，用户关闭该任务。
2. 隔离工作区、临时终端与后台资源静默回收，侧边栏瞬间清爽，只留下仍在推进的焦点。
3. 这份包含目标边界、审查往返、验证证据与 PR 链接的只读报告永久留档——几个月后想查“当初为什么这样改”，搜一下标题十秒就能翻出完整来龙去脉。

## 二、逆风流程：真实开发最常发生的 3 种异常 User Flow

顺风局用什么工具都显得轻松；真正决定开发体验上限的，是下面三种每天都在发生的脏场景。

### 异常流 A · 审查反复打回或两路意见打架（自动熔断与快速裁决）

- **发生场景**：实现提交后被独立审查打回，修复一轮又引入新回归；或者两路并行审查互相矛盾（一方要求拆细抽象，另一方认为过度设计），继续自动跑下去只会空转烧额度。
- **理想 User Flow**：
  1. 达到返工阈值或检测到明显分歧时，系统**自动熔断暂停**，在侧边栏 `Focus` 置顶提示需要人工裁决；
  2. 用户点进任务，不用自己通读两份长评审记录——主屏直接浓缩出 **“当前卡住的核心分歧 + 双方论据要点 + 2–3 个清晰裁决选项”**；
  3. 用户 15 秒选定方向（或边栏补一句原则），系统立刻沿裁决恢复推进。

### 异常流 B · 临门一脚上游主干变了（自动 Rebase 与分级重验）

- **发生场景**：多条任务并行推进时，另一条 PR 先合入了主干，导致当前已审完、准备合并的分支落后或出现合并冲突。
- **理想 User Flow**：
  1. 系统感知上游变化后，先在隔离区自动尝试变基并重跑验证；
  2. **若为纯机械变基且全量验证仍全绿**：静默刷新绿灯状态，不打扰用户，直接保持可合并状态；
  3. **若存在代码冲突或行为语义变化**：在侧边栏 `Focus` 精准冒泡，主屏高亮冲突范围与变动影响；解决冲突后自动触发增量复审与重验，确认无回归再回到 Ready to Merge。

### 异常流 C · 干到一半假设推翻或需求大改（干净转向）

- **发生场景**：写到一半发现底层约束不成立，或用户在边栏决定换一条完全不同的方案。
- **理想 User Flow**：
  1. 用户直接在边栏提出转向指令，不需要手动删分支、清文件或另起一个新任务；
  2. 系统干净中止旧执行流、安全回退未提交的脏改动，将主屏的《目标与边界》原地刷新为新共识（旧尝试折叠进历史，不污染当前视线），原地轻装重新出发。

## 三、检验这套场景设计的 4 条产品标尺

1. **零配置起跑，纪律隐形继承**：在同一个仓库开第 2 条、第 20 条任务时，用户贴一句话即可自然带齐验证与审查纪律，几乎感觉不到“流程配置”的存在。
2. **平时绝对安静，例外精准冒泡**：多轨并行全靠侧边栏 `Focus` 极简三档信号驱动，不靠噪音和重型大盘消耗精力。
3. **用“导览看核心代码”替代“盲信文字摘要”**：既不让用户淹没在几千行原始 Diff 里，也不逼用户闭眼相信 AI 的两句话总结。
4. **永远握着方向盘，随时优雅转向**：顺风时全自动跑完，逆风时能一跳直达现场纠偏、15 秒裁决分歧、一键干净重来。
