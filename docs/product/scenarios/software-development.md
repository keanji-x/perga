# 场景一：软件开发闭环产品设计

软件开发是 Perga 现阶段**首个重点打磨的端到端闭环**（对应内置协议 [`agents-delivery`](../../../templates/agents-delivery)）。本文不讨论底层架构实现，只从**开发者真实工作体感**出发，定义这条闭环应该交付什么样的最佳体验，以及当前最需要打磨的体验断点。

## 核心体验目标

> **让开发者从“在十个终端里当 AI 保姆”，变成只做三个高杠杆动作的 Tech Lead：定边界 → 偶尔纠偏 → 看证据放行。**

Perga 在软件开发场景里不与单厂 CLI 拼“生成一行代码有多快”，而是交付另一种确定性：**当你同时推进 3–8 个跨小时乃至跨数天的复杂 PR 时，既不需要反复切窗口盯梢，也不用闭眼盲信合并。**

---

## 五步黄金闭环

围绕一个真实复杂需求（特性开发、架构重构、难啃的线上 Bug）走完完整生命周期：

### 1. 起手：贴需求即开跑，零前置表单（0–60 秒）

- **用户动作**：在项目对应的 Area 下新建 Track，只贴一句话需求或一个 GitHub Issue 链接，直接发送。
- **理想体验**：
  - 不弹窗强迫用户选模板、填测试命令、配审查模型；
  - 后台静默准备好隔离工作区（OverlayFS 共享预热缓存 / `jj` / Git worktree / SSH）；
  - Lead 先做**只读侦察**（读取仓库 `AGENTS.md`、关联模块与既有契约），而不是闷头改代码；
  - 在左侧主屏立出一份 **30 秒能读完的《目标与边界》**（要改什么、不改什么、如何验证），仅在存在真实歧义时于边栏提出 1–2 个选择题。

### 2. 定锚：3 分钟对齐边界，然后放心离手

- **用户动作**：扫一眼左侧方案与将要执行的阶段拓扑（实现 → 异构双路独立 Review → 全量验证 → 提 PR 与 CI 守望），在边栏补一句约束（例如“别动公开契约，Review 走指定只读模型，开始吧”）。
- **理想体验**：
  - 确认后，主屏亮起干净只读的 `builtin:flow` 进度拓扑并开始自动推进；
  - **关键体感**：用户此时可以**立刻切去侧边栏里的下一条 Track**，或离开电脑——因为执行路径、写入强制门禁（`requireGateForReadWrite`）与审查异构路由（`routing.enforce`）已由系统锁死，不再依赖口头提醒。

### 3. 运行中：默认绝对安静，异常精准冒泡，随时一跳直达现场

- **用户动作**：推进过程中无需盯盘，仅通过**侧边栏 `Focus`** 感知哪条 Track 真正需要自己介入。
- **理想体验**：
  - 正常推进阶段（实现、并行双审、门禁运行、0-Token `watch` 盯 PR CI）保持绝对安静，不弹窗、不刷屏；
  - 当用户主动巡看或侧边栏提示异常时，点进 Track **不必翻几百行聊天记录**——主屏 `Flow` 一眼定位当前卡点（如某路 Review 标出 `attention` / `blocked`），紧贴节点下方以极简脚注展示门禁状态（`✓` / 运行中 / `×`）与代码/文档引用；
  - **点击节点上的模型署名，直接进入对应 Worker 实时对话流**，随时发一句 `Steer` 把跑偏的思路拉回，或中断、切换模型继续执行。后台自治，但永远不是黑盒。

### 4. 收口：十秒「交付证据简报」，桌面或手机从容签字

- **用户动作**：侧边栏 `Focus` 提示这条 Track 已收口待放行（所有审查阻塞项清零、全量门禁通过、PR 已创建且 CI 全绿）。
- **理想体验**：
  - 传统工具在收口时只甩出一大坨 raw diff 与零散日志，逼人在“看半小时”和“闭眼盲合”之间二选一；
  - Perga 的理想收口是在主屏自然收束出一份 **十秒可读的交付证明（Proof of Work）**：
    1. **改动地图**：两句话交付结果 + 关键修改文件清单（点击文件名直接侧滑查看干净 Diff 或跳转 PR）；
    2. **异构审查结论**：另一家独立只读模型挑出了哪几个问题、分别如何修复、复审确认零阻塞；
    3. **不可伪造的内核绿灯**：实际执行过的测试门禁命令、退出结果与 PR CI checks 全绿状态；
    4. **风险与边界提示**：是否涉及迁移、外部契约变更或已知未覆盖项。
  - 无论在桌面还是移动端 PWA，人扫完这四块硬证据就能心里有底地批准合并。

### 5. 归档：合完即净，决策留痕

- **用户动作**：确认合并 PR，关闭 Track。
- **理想体验**：
  - 后台静默卸载并清理隔离工作区、回收终端与会话资源；
  - 侧边栏立刻清爽，只留下仍在推进的焦点；
  - 完整的目标边界、审查往返、测试证据与 PR 链接永久沉淀在只读 Report 中，数月后随时可查“当时为什么这样改”。

## 当前最值得打磨的 3 个体验断点

对照上述五步闭环，现有 [`agents-delivery`](../../../templates/agents-delivery)（28 行 `template.perga.js` + 5 行 `report.md`）已将底层机制跑通，但从产品体验来看，仍有三处最直接影响“顺手程度”的断点值得优先打磨：

### 断点 1：消掉“模板 / 协议”的感知门槛（仓库级默认偏好）

- **现状摩擦**：新开一条 Track 默认是裸状态，跑完整交付闭环仍需要人或 Lead 主动挂载 `agents-delivery` 并确认 `testCmd` 与 `reviewModel`。
- **打磨方向**：将“这个仓库怎么验证、偏爱哪个审查模型、默认要不要走交付闭环”沉淀为 **Area（代码仓库）级别的默认偏好**（并在首次接入仓库时从 `AGENTS.md` 自动探测建议）。用户在同一个仓库开第 2 条、第 20 条 Track 时，贴一句话即自动带齐纪律，无需感知“模板配置”的存在。

### 断点 2：侧边栏 `Focus` 信号的极克制三档分级

- **现状定位**：开发者多轨并行时，主入口就是**侧边栏 `Focus`**，不需要为了切任务特意去逛一个厚重的全局大盘页面。
- **打磨方向**：为了支撑 5–10 条开发轨道并行而不制造小红点焦虑，侧边栏 `Focus` 的视觉信号应严格压成三档：
  1. **等你拍板 / 需要救火**（最高优显眼）：待确认审批、节点进入 `blocked` / `attention`、或 PR 已全绿待合并；
  2. **静默运转中**（极弱呼吸态）：Worker 正在实现/审查、或 0-Token `watch` 正在等 CI，绝不抢注意力；
  3. **安静待看**（轻提示）：普通阶段更新，不催促。
- 目标日常节奏：**扫一眼 Focus → 只点亮着“等你拍板”的那 1–2 条 → 十秒看证据、Steer 或放行 → 切回下一条。**

### 断点 3：强化 `Ready to Merge` 一刻的证据收束感

- **现状摩擦**：`builtin:flow` 已经把**执行过程**呈现得很干净，但在最后一秒决定“要不要合并 PR”时，开发者最需要把 **Diff 入口、异构 Review 修复摘要、以及内核 Gate / CI 全绿证据** 收在同一个视线流里，而不是分头去点不同面板。
- **打磨方向**：把“过程拓扑（Flow）”与“终局交付摘要（Ready-to-Merge 证据收束）”在视觉和交互上衔接得一气呵成，保证在桌面端和手机端都能十秒扫完、一键下钻关键文件 Diff，把最后一公里的信任感拉满。

---

## 当前真实边界

- 单人并行推进多条相对独立的复杂 PR 已经顺滑；
- 当多条 Track 强耦合修改同一组核心文件时，跨轨道的合并顺序与冲突编排目前仍需人工统筹（归入 [design.md](../design.md) 的 P3 演进项）。
