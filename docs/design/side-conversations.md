# Side conversations

The desktop composer opens a side draft with a frozen excerpt of the source conversation. Sending the first question creates an independent session through the existing keyed session creation endpoint. The first user message and session title contain the question. A separate optional `sourceExcerpt` is frozen with that turn. The Kernel includes it in the first provider input, including when dispatch resumes after restart. Later turns send only their own input.

The v1 bootstrap advertises `conversationSide` when the Host accepts `sourceSessionId` and `sourceExcerpt` at creation and returns the source link on reads. A cached web client can reconnect to an older v1 Host that cannot create linked sessions. Keep this capability until the minimum supported Host implements side creation and the compatibility gate enforces that minimum. The Kernel resolves the source in the current Track before provider discovery and rechecks it at commit. The source identifies the discussion shown in the side pane. Session ownership and permissions continue to come from the authenticated creator.

SQLite migration 0029 adds a nullable source reference. Existing sessions have no recorded source. The existing creation transaction commits the reference, first input and receipt together. Migration 0030 stores the excerpt on the accepted turn and indexes non-null source references for foreign-key updates. The source and excerpt participate in the creation hash when present. Check replay after restart, a source from another Track, and reopening the side pane from its original conversation.
