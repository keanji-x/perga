Perga 通知、定时器与消息调度统一大架构

核心铁律 业务入口只做「同事务落库 + 调 SessionTurnScheduler.Poke()」，不再自行判断闲/忙或直接拉起 Turn
显式消息队列 (session_messages) 统一系统唤醒箱 (track_wakes) 唯一仲裁层 (SessionTurnScheduler) 纯粹执行层 (SessionTurnRunner) 独立边界（不进异步唤醒队列）

1. 入口分叉与并发状态集合

改造前 · 散做一团
8 个入口各自手写闲/忙判断与预约锁；并发互斥分散在 _activeTurns、_reservedWakeSessions、_compactingSessions、_steering、_sessionResumeHolds、_dispatchingInputs、HoldsDurableSlot 7 处，且相互漏检（如 wake 漏检 _steering 与 Messages.NextAsync）。
改造后 · 单一真源
所有入口只落库并调用 SessionTurnScheduler.Poke()。7 个集合收敛为清晰的每会话单一状态机（Idle / Running / Compacting / Resuming / BlockedUnknown），全系统只在 TryScheduleNext 一处裁决互斥与优先级。

2. 唤醒持久性与纯日志审计

改造前 · 只有 Mail 持久化
仅 Mail 写 mails.wake_pending 并计入 _queuedMailWakes；Task 结算、Schedule、Ask 回答、Report 编辑全在纯内存 _pendingWakes 且不计入 HasActiveWork，Actor 空闲驱逐或进程重启直接静默丢失。
改造后 · 纯日志 Outbox + 维护裁剪
6 类系统唤醒同事务写入 track_wakes，零运行期 DELETE，单调记录 reason / turn_id / attempts 便于排障；运行期失败立刻 Fail Fast 回 idle，终态由既有 RunMaintenancePassAsync（7 天 / 5 万条）按批裁剪。

3. 切换 Lead / 关 Track / 切模板取消

改造前 · 错发与计数泄漏
DispatchLeadWakePromptIfNeededAsync 入队时写死 oldLeadId，切换 Lead 后不会迁移 _pendingWakes，导致通知错发给已降级的 Subagent；关闭 Track 不清内存队列，_queuedMailWakes > 0 致 Actor 永不驱逐。
改造后 · 动态绑定与原子作废
target_session_id = NULL 在领取时刻动态解析最新 LeadSessionId，切 Lead 只需 Poke(newLead)；内部 CancelPendingWakeAsync 接入关 Track（track_closed）与切模板（template_changed），零泄漏且保留取消日志。

4. 执行引擎 · 用户排队合并 · Turn 级结算

改造前 · 520 行大泥球 + 逐条强绑
ExecuteSessionTurnPipelineAsync 混杂 5 套分支与死代码；0006 唯一索引强绑 1 条消息 1 个 Turn，多条排队用户消息必须逐轮跑 SessionInputs 单行更新。
改造后 · Runner + 用户批合 Turn 结算
SessionTurnRunner 对接 SessionInputBatchWorkItem / WorkerMessageWorkItem / TrackWakeBatchWorkItem；排队用户消息可逐条撤回 / Steer，出队合进 1 个 turn_id，unknown 一键整批解锁，修复 SessionInputs 5 处单行假设，不做逐条失败归因。

5. Cronos 定时调度与 Fail Fast（零缓存）

改造前 · 全量查表 + 提前改脏
每 15s 对每个开放 Track 调全量 LoadTrackAggregateAsync（查 5 张表）并重编译模板；TriggerScheduleWakeAsync 在入队前就跑 BuildScheduleWakePrompt（如 checkInCount++），唤醒若丢则状态永久错位。
改造后 · 轻查 + 延迟求值 + 不缓存
Host 改单表轻查询（停机错过不补发）；领取开 Turn 时才求值，schedule 遇无证据故障直接 Fail Fast 标 dropped(runtime_failed)（重启亦标 boot_dropped），天然至多执行一次——无需缓存求值结果、不建水位表、无死循环。

6. 两阶段重启恢复与前端渲染

改造前 · 4 轮抢槽 + 错显 Owner
BootReconciler 分 4 轮各自向 Actor 发恢复调用互相抢槽；UpsertMailAsync 应用层判开/闭存在竞态；前端 conversation-display.ts 只认 wake / scheduler 漏掉 system，重启通知误显为 Owner。
改造后 · 先纯 DB 收敛 + 单次 Poke
Step 1 纯 DB 收敛（按 turn_id 分组恢复用户输入、同事务写 boot、关键 3 类 delivering 先去冲突再退 pending、非关键标 boot_dropped），Step 2 每轨只调一次 Poke()；修前端 system 判别与 UpsertMail SQL 开轨守卫。

3. 0011_track_wakes.sql（纯 DDL，无历史回填）

CREATE TABLE track_wakes (
    ordinal           INTEGER PRIMARY KEY AUTOINCREMENT,
    id                TEXT NOT NULL UNIQUE,
    track_id          TEXT NOT NULL REFERENCES tracks(id) ON DELETE CASCADE,
    target_session_id TEXT REFERENCES agent_sessions(id) ON DELETE CASCADE,
    kind              TEXT NOT NULL CHECK (kind IN (
                          'mail', 'schedule', 'task_settled',
                          'ask_answered', 'report_edited', 'boot'
                      )),
    coalesce_key      TEXT,
    payload_json      TEXT NOT NULL DEFAULT '{}',
    state             TEXT NOT NULL CHECK (state IN (
                          'pending', 'delivering', 'done', 'dropped'
                      )),
    reason            TEXT,
    turn_id           TEXT,
    attempts          INTEGER NOT NULL DEFAULT 0,
    created_at_ms     INTEGER NOT NULL,
    updated_at_ms     INTEGER NOT NULL
);

CREATE UNIQUE INDEX idx_track_wakes_coalesce_pending
    ON track_wakes(track_id, coalesce_key)
    WHERE state = 'pending' AND coalesce_key IS NOT NULL;
CREATE INDEX idx_track_wakes_active
    ON track_wakes(track_id, state, ordinal) WHERE state IN ('pending', 'delivering');
CREATE INDEX idx_track_wakes_gc
    ON track_wakes(state, updated_at_ms, ordinal) WHERE state IN ('done', 'dropped');

-- 允许同一 turn_id 合并多条 queued 用户消息（保留索引名兼容 SqliteMigratorTests）
DROP INDEX idx_session_messages_input_turn;
CREATE INDEX idx_session_messages_input_turn
    ON session_messages(turn_id) WHERE source = 'session' AND turn_id IS NOT NULL;

-- ② BootReconciler 重启三步收敛
UPDATE track_wakes SET state = 'dropped', reason = 'boot_superseded', updated_at_ms = @Now
WHERE state = 'delivering' AND coalesce_key IS NOT NULL
  AND EXISTS (SELECT 1 FROM track_wakes p
              WHERE p.track_id = track_wakes.track_id AND p.coalesce_key = track_wakes.coalesce_key AND p.state = 'pending');
UPDATE track_wakes SET state = 'dropped', reason = 'boot_dropped', updated_at_ms = @Now
WHERE state = 'delivering' AND kind IN ('schedule', 'report_edited', 'boot');
UPDATE track_wakes SET state = 'pending', reason = 'boot_requeued', turn_id = NULL, updated_at_ms = @Now
WHERE state = 'delivering' AND kind IN ('mail', 'task_settled', 'ask_answered');

-- ③ RunMaintenancePassAsync 定期裁剪（7 天 + 5 万终态上限，每批 LIMIT 1000）

    SELECT ordinal FROM track_wakes WHERE state IN ('done', 'dropped') AND ordinal <= @Cutoff ORDER BY ordinal LIMIT 1000
