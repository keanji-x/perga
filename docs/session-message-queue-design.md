# 共用会话消息队列

设计草稿 · 2026-11-18 · [Issue #21](https://github.com/keanji-x/perga/issues/21)

普通会话和 Worker 共用消息身份、送达记录和会话时间线。浏览器和 MCP 继续使用原请求键重试。Kernel 在同一个地方决定下一条消息何时可以发，以及它能否进入指定轮次。

## 实现

迁移 0006 将 `session_inputs` 和 `worker_messages` 的回执复制到 `session_messages`，并把旧时间线条目关联到同一个消息身份。此次升级会按现有迁移流程保留升级前的数据库备份。旧版内存等待队列没有可迁移的数据，升级前可以等它排空。

浏览器的普通会话和 Worker 共用队列列表和撤回入口。Lead 可以用 `perga_session_withdraw` 撤回等待中的 Worker 消息，也可以用 `perga_session_steer_queued` 把它送入明确指定的当前轮次。

## 消息身份与操作

消息先有稳定的 `messageId`。每条消息记录会话、发起者、请求键、请求内容摘要、提交时间和送达结果。Worker 消息还记录 Attempt ID。普通发送和排队可以先落库，再在领取时关联轮次。一个轮次可以关联多个消息。Steer 的 `targetTurnId` 在受理时写入，后续重试始终使用原轮次。取得 provider 送达证据后，记录实际的 `deliveredTurnId`。

| 操作 | 受理条件与结果 |
| --- | --- |
| 发送 | 会话可以开始下一轮。Worker 明确继续时，恢复同一 Attempt 的执行，不改变工作区绑定。 |
| 排队 | 保存消息并按受理顺序等待。暂停的 Worker 保持暂停。 |
| Steer | 校验当前轮次和原生能力。目标发生变化时拒绝该请求，并返回该请求键已有的送达结果（若有）。 |
| 撤回 | 只撤回尚未被调度器领取的消息。领取和撤回对同一条记录做原子状态转换。 |
| 重试 | 按会话、发起者和请求键查原记录。同键同内容返回原结果，同键不同内容返回冲突。 |

调度器持久化发送意图后才调用 provider。`queued` 表示尚未领取，`dispatching` 表示已领取，`delivered` 表示获得 provider 的送达证据。`rejected`、`withdrawn` 和 `interrupted` 分别记录拒绝、撤回和执行生命周期结束。`unknown` 表示请求可能已经送达。轮次的开始、完成、失败和中断继续由轮次记录表达。发送一条消息和整个轮次取得结果可以发生在不同时间。

## 重启与并发

同一会话的 Actor 在取得执行槽时重查当前轮次和 Attempt。普通会话可恢复仍为 `queued` 的消息。Host 重启会回收在途 Worker 的租约、结束旧 Attempt 并归档旧会话。余下等待中的 Worker 消息标记为 `interrupted`。人或 Lead 重新派发时建立新的 Attempt、会话和队列。原会话的历史和收据仍可查。重启后，尚无确认的 `dispatching` 转为 `unknown`，请求键仍指向原消息。系统在取得明确结果前保持送达未知状态。

普通会话的直接 Steer 要求指定仍在运行的轮次。已有队列消息的每次 Steer 按消息及目标轮次保存回执。若系统确定没有向目标发送，已排队的消息可以继续等候。撤回仅受理尚未绑定轮次的等待消息。

Provider 调用在 Actor 外执行，Actor 负责领取、状态转换和轮次关联。完成回调核对消息和原执行身份。Worker 首轮启动、暂停、继续与 Task 验证的租约规则继续生效。消息队列只能在这些条件允许时继续发。

## 迁移和历史

发布新的前向迁移创建共用消息表和索引，保留所有已发布迁移的内容。把 `session_inputs` 和 `worker_messages` 的既有标识、请求键、已知轮次和送达证据迁移到共用读取契约。用来源表和既有标识保留可查的旧收据，遇到不同来源的标识碰撞时仍能区分。旧记录缺少目标或送达证据时保留缺省或 `unknown`。旧版内存等待队列没有可迁移的数据，切换前由运维按需等待它排空。

切换后，由一个 Kernel 路径写入新消息。旧 API 需要兼容时，通过同一记录生成旧收据，历史轮次与条目继续可读。时间线用 `messageId` 对齐排队预览、当轮 Steer 和已落库条目，实际绑定轮次后移除排队预览。迁移验证重点是恢复旧数据后仍能重放原请求键，以及同一条消息只有一个展示身份。

## 验收

1. 用包含旧输入和 Worker 收据的数据库升级，验证历史、请求重放和会话归属。
2. 验证双入口并发入队、领取与撤回竞态、精确轮次 Steer、暂停后继续，以及多条消息绑定同一轮次。
3. 在领取前、领取后和 provider 回执后分别模拟进程重启。验证只有已知未发送且仍有执行资格的消息会自动继续，`unknown` 保留可查。
4. 用实际浏览器验证排队、撤回、时间线衔接和断线反馈。改动涉及持久化和恢复，按 L2 评审并运行完整 .NET 测试。
