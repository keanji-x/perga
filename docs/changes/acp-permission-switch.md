# Session runtime settings reconciliation

Outcome: permission updates persist desired settings without launching discovery or closing idle processes. Session reuse reconciles model, reasoning effort and permission together before dispatch. Review tier: L2; independent reviews are arranged by the Planner. No storage migration or frontend change.

`RuntimePermissionModes` resolves synchronously in memory. Native providers use the static AgentKit catalogue and default. ACP null requests retain the provider default; explicit requests are trimmed and accepted without discovery. Only the same session’s open handle, with the same provider and no resume hold, can supply a nonempty catalogue for early validation. Updates do not mount workspaces, enter probe admission, or block drain. Task-bound updates and blank PUT values remain InvalidArgument.

TrackActor owns one `OpenSessionHandle` containing the agent, launch specification and last reconciled `SessionRuntimeSettings`. Removing a handle removes all its metadata on provider changes, worker settlement, resume, context reset, teardown and eviction. Persisted desired settings are authoritative; a failed reconciliation never permits a prompt on the previous settings. Active turns retain their snapshot; queued turns, wakes and compaction reconcile the latest settings at their next open boundary.

AgentKit exposes `IAgentSession.TryReconcileSettingsAsync`. ACP tracks its applied settings, permission config ID and modes that require launch arguments. Ordinary modes use `session/set_mode` or `session/set_config_option` in place, then reconcile the model. Method-not-found returns false so Kernel disposes and resumes a fresh process. Invalid modes throw explicitly during both cold initialization and hot reconciliation. Reset to null and transitions into or out of launch-argument modes return false. AgentRuntime supplies Antigravity’s bypassPermissions launch mode; ACP and Kernel contain no provider-name-specific switching policy. Native providers reopen when permission changes and retain their existing model behavior.

Dynamic permission catalogue correction after the L2 protocol review of `82f201355178e30b2090b9c4722eeee0eadf61fd`:

The provider's latest advertised catalogue is authoritative for hot validation and transport selection. `AcpAgentSession.RefreshPermissionModes` parses only payloads carrying `configOptions` or `modes`, merges the saved launch-time `extraPermissionModes` by ID, and publishes a read-only options list and config ID in one `Volatile` snapshot. Validation and its outgoing mode request retain the same snapshot. Antigravity's injected `bypassPermissions` remains available and still requires restart; removed provider modes are rejected before an RPC. An empty `{}` success response preserves the catalogue and transport.

Initialization, permission-setting responses, model-setting responses through the `session/set_config_option` fallback, and matching-session `config_option_update` notifications all use this refresh method. Notifications refresh ordinary sessions as well as Workers. Notifications with another or blank session ID cannot replace the catalogue. Response refresh runs inside the JSON-RPC result observer before the reader processes following notifications, preventing an older response continuation from overwriting a newer notification.

Idle reuse correction after the L2 concurrency review of `f7c3ed16a02e9530ffac1ff8de33b393a299b8a9`:

Every idle reuse boundary now calls `IAgentSession.TryReconcileSettingsAsync`, including when desired settings equal the handle's recorded settings. The session owns the current provider constraints. TrackActor retains its existing remove/dispose behavior on rejection or reopen fallback. ACP already validates the desired mode against one latest catalogue snapshot before comparing applied settings; this ordering remains unchanged. Thus an unchanged valid request makes no settings RPC, while a removed mode throws before prompt dispatch. Codex and Claude retain their opening settings and accept equality without RPC; changed settings still require reopen. Both Kernel and Host runtime fakes track successful applied settings and avoid counting unchanged reuse as a model or permission switch. No persistence, migration or frontend change; review tier remains L2, with formal reviews arranged by the Planner.
