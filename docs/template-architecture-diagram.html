Layer 1 · Data Model：响应式状态机四元组 ⟨State, Events, Rules, Views⟩ Kernel / PolicyVm / Closed & Complete
① State记忆
  • config：外部配置参数，支持热调不丢历史
  • state：运行演化出的持久化事实状态
② Events4 类封闭边界
  • Time：周期 / 一次性触发点
  • Task：派发前 / 结算后
  • Tool：外部工具调用前
  • Turn / Report：开轮 / 提交前
③ Rules裁决与演化
  • 事前 before:*：Allow / Deny / AskHuman / Rewrite
  • 事后 after:*：更新 state + 唤醒或登记定时
④ Views纯函数投影
  • f(config, state, timers)
  • 输出 badges · notice · metrics · rules，零副作用
声明式语法糖（编译为 Rules）：tasks.routing → before:task.dispatch · report.sections → before:report.commit 组合机制：extends 继承合并（Rules 串联）· 静态底座依赖 requires（插件/工作区）
↓ Views 纯投影（Fail-Soft 降级）· 按数据存在自适应降维 ↓
Layer 2 · View：Report 页面双轨呈现（读写分离，互不覆盖） Frontend / Zero Hardcoding
轨道 A · 顶部协议与活面板 来自 ④ Views + Kernel
  • 无模板：整块隐藏，零干扰。
  • 默认态：单行协议条（模板名 + ≤3 胶囊 + 下次时间事件）。
  • 按需展开：有 notice 展提示条；有 metrics 展 ≤4 格指标与折线微图。
  • 抽屉（动态 Tab）：口径与规范 · 调度与日志 · 运行参数（热调）· 协议定义。
轨道 B · 叙事正文与内嵌活块 Human + Planner
  • 无正文时：自然落入干净 ReportEmpty（彻底移除占位文本）。
  • 有正文时：仅渲染已写章节；hover/focus 才浮现轻量编辑按钮。
  • 重型数据/图：复用原生 view / table / chart.series 穿插正文。
  • 极端定制：使用现有沙盒 html 块逃生舱，顶栏永不膨胀。
